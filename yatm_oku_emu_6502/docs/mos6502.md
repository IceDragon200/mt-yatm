# MOS 6502 Emulator Contract

This document is the behavioral contract for OKU's MOS 6502 implementations.
Both `LuaChip` and `NativeChip` SHALL produce the same externally observable
result. Unless stated otherwise, "6502" means the original NMOS MOS 6502: this
does not specify 65C02 extensions or undocumented opcodes.

The emulator is instruction-stepped rather than cycle-accurate. Instruction
results, registers, flags, memory accesses, vectors, stack layout, and relevant
NMOS quirks SHALL be accurate. Exact per-cycle bus activity is currently out of
scope, except for the reset sequence exposed by `step()`.

The implementation was originally based on:

  -- opcode encodings, addressing modes, flags, and instruction behavior.
* [Internals of BRK/IRQ/NMI/RESET](https://www.pagetable.com/?p=410) -- interrupt
  and reset sequencing.
* [Microtan Java emulator](http://oric.free.fr/microtan/microtan_java.html) --
  historical implementation reference; the page may no longer be available.
* [Klaus Dormann's functional tests](https://github.com/Klaus2m5/6502_65C02_functional_tests)
  -- separate general, interrupt, and Bruce Clark decimal-mode programs.
* [Bruce Clark's decimal-mode test](https://github.com/Klaus2m5/6502_65C02_functional_tests/blob/master/6502_decimal_test.a65)
  -- public-domain exhaustive NMOS arithmetic prediction algorithm. Clark's
  work is the behavioral basis for this project's independent decimal oracle.
* [SingleStepTests 65x02](https://github.com/SingleStepTests/65x02) --
  per-instruction initial/final states and bus-cycle traces for differential
  spot checks.
* [Visual6502](https://visual6502.org/) -- transistor-level NMOS behavior for
  resolving disagreements between higher-level references.

Where a secondary source and original NMOS hardware behavior disagree, verified
NMOS behavior wins. A regression test SHOULD accompany every resolved ambiguity.

## Machine State

The programmer-visible state is:

| Register | Width | Purpose |
| --- | ---: | --- |
| `PC` | 16 | Program counter |
| `A` | 8 | Accumulator |
| `X` | 8 | X index register |
| `Y` | 8 | Y index register |
| `SP` | 8 | Offset into stack page `$0100..$01FF` |
| `P` / `SR` | 8 | Processor status, `NV-BDIZC` |

All 8-bit registers wrap modulo 256 and `PC` wraps modulo 65536. The status
bits are:

| Bit | Name | Meaning |
| ---: | --- | --- |
| 7 | `N` | Copy of result bit 7 |
| 6 | `V` | Signed arithmetic overflow |
| 5 | unused | Not a writable physical flag; reads/pushed values conventionally show 1 |
| 4 | `B` | Not a physical flag; synthesized in status values pushed by `BRK`/`PHP` |
| 3 | `D` | Decimal (BCD) arithmetic mode |
| 2 | `I` | Maskable IRQ disable |
| 1 | `Z` | Result is zero |
| 0 | `C` | Carry, no-borrow, or shifted-out bit depending on the instruction |

`B` SHALL NOT persist as ordinary processor state. `PLP` and `RTI` SHALL ignore
the pulled `B` bit. Tests compare status using the behavior above rather than
treating all eight bits as independent latches.

## Memory and Addressing

The address space is exactly 65536 bytes, `$0000..$FFFF`. Sixteen-bit values and
vectors are little-endian: low byte first, then high byte.

| Mode | Bytes | Effective operand/address |
| --- | ---: | --- |
| implied / accumulator | 1 | Instruction-defined register, usually `A` |
| immediate | 2 | Byte at `PC + 1` |
| zero page | 2 | `$00nn` |
| zero page,X | 2 | `$00((nn + X) & FF)` |
| zero page,Y | 2 | `$00((nn + Y) & FF)` |
| absolute | 3 | Little-endian word following opcode |
| absolute,X | 3 | `word + X`, modulo 65536 |
| absolute,Y | 3 | `word + Y`, modulo 65536 |
| (indirect,X) | 2 | Zero-page pointer at `(nn + X) & FF`; pointer high-byte lookup wraps in zero page |
| (indirect),Y | 2 | Zero-page pointer at `nn`; pointer high-byte lookup wraps in zero page, then add `Y` |
| indirect | 3 | Pointer used only by `JMP` |
| relative | 2 | Address after operand plus signed 8-bit displacement (-128..127) |

NMOS quirks are normative:

* Zero-page indexing and zero-page pointer reads wrap at `$00FF` to `$0000`.
* `JMP ($xxFF)` reads its high target byte from `$xx00`, not `$(xx+1)00`.
* The hardware stack wraps within page 1; exhaustion is not an emulator fault.
* Page-cross timing penalties need not be modeled until cycle accounting is made
  part of the public contract.

## Reset and Vectors

| Vector | Address |
| --- | ---: |
| NMI | `$FFFA..$FFFB` |
| RESET | `$FFFC..$FFFD` |
| IRQ / BRK | `$FFFE..$FFFF` |

Reset obtains `PC` from the little-endian RESET vector and sets `I`. The NMOS
sequence takes seven bus cycles before opcode execution; OKU exposes its reset
progress through repeated `step()` calls and enters `CPU_STATE_RUN` when the
sequence completes. `A`, `X`, and `Y` have no hardware-defined reset values and
tests SHALL NOT require particular values for them.

The reset sequence performs three stack reads while decrementing `SP`, rather
than writes. Consequently reset changes `SP` by -3 modulo 256. This detail and
the exact initial power-on `SP` chosen by OKU must be pinned by reset tests before
the startup implementation is considered cycle-compatible.

## Stack, Subroutines, and Interrupts

A push writes to `$0100 + SP`, then decrements `SP`. A pull increments `SP`, then
reads `$0100 + SP`.

`JSR` pushes the address of the final byte of its own instruction (`PC + 2` as
measured from the opcode), high byte then low byte. `RTS` pulls low then high and
continues at the pulled address plus one.

`BRK` consumes a padding byte, pushes `PC + 2` high then low, pushes status with
`B` and bit 5 set, sets `I`, and loads the IRQ/BRK vector. A hardware IRQ/NMI
pushes the current `PC` high then low and status with `B` clear and bit 5 set.
`RTI` pulls status, then `PC` low and high, without incrementing the restored PC.

## Instruction Semantics

* Loads and transfers to `A`, `X`, or `Y` set `N` and `Z`. Stores and `TXS` do
  not affect flags.
* `AND`, `EOR`, and `ORA` write `A` and set `N`/`Z`.
* `ASL`, `LSR`, `ROL`, and `ROR` set `C` from the shifted-out bit and set `N`/`Z`
  from the result. Rotates shift the old `C` into the result.
* `INC`, `DEC`, `INX`, `INY`, `DEX`, and `DEY` wrap at 8 bits and set `N`/`Z`.
* `CMP`, `CPX`, and `CPY` leave registers unchanged and set `C` when
  `register >= operand`, `Z` on equality, and `N` from bit 7 of the wrapped
  subtraction.
* `BIT` leaves `A` unchanged, sets `Z` from `(A & operand) == 0`, and copies
  operand bits 7 and 6 to `N` and `V`.
* Binary `ADC` computes `A + operand + C`; binary `SBC` computes
  `A - operand - (1 - C)`. Both set `N`, `Z`, `C`, and signed `V` correctly.
* With `D` set, `ADC` and `SBC` use NMOS packed-BCD behavior. Decimal-mode flag
  results require dedicated exhaustive vectors; they SHALL NOT be inferred from
  65C02 behavior.
* Branches test exactly one flag and otherwise preserve registers and flags.
* Flag instructions alter only their named flag. `NOP` changes no programmer-
  visible state other than `PC`.

## Conformance Plan

Every behavioral test SHALL run unchanged against every available subject
(`LuaChip`, then `NativeChip`). Expected results come from this contract or an
independent oracle, never from one implementation.

1. Reset vector, reset state, 16-bit wrapping, and memory boundaries.
2. All addressing modes, including zero-page wrap, signed backward branches,
   page crossing, and the NMOS indirect-`JMP` bug.
3. Loads, stores, transfers, flag set/clear, and `NOP`.
4. Stack wrap, push/pull ordering, nested `JSR`/`RTS`, `BRK`, and `RTI`.
5. Logic, compare, `BIT`, increment/decrement, shifts, and rotates using boundary
   vectors plus randomized oracle checks.
6. Binary `ADC`/`SBC` exhaustively over both operands and carry-in.
7. Decimal `ADC`/`SBC` using an independently sourced NMOS truth table.
8. All branch taken/not-taken cases, forward/backward offsets, and PC wrap.
9. IRQ and NMI once the external interrupt interface is defined.
10. Run the bundled functional binary to its documented success loop, with an
    instruction ceiling and failure-PC diagnostics.

An instruction family is complete only when every official encoding is tested,
both backends pass the same vectors, flags are asserted independently, and all
known NMOS edge cases for that family have explicit regressions.
